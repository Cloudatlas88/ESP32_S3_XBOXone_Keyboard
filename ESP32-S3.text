# 项目：ESP32-S3 游戏手柄改造为 USB HID 键盘

## 角色设定
你是一位资深嵌入式系统工程师，精通 ESP-IDF、TinyUSB、FreeRTOS、USB HID 协议、NVS 存储、看门狗机制及 Windows HID 上位机开发。请基于以下完整需求，协助我完成项目架构设计、模块划分、关键代码实现和测试方案。

## 1. 项目目标
将游戏手柄通过 ESP32-S3 N16R8 改造成一个 USB 有线 HID 键盘，连接电脑后完全模拟实体键盘，支持按键映射、宏功能、上位机配置、NVS 断电保存和故障保护。

## 2. 硬件平台
- MCU：ESP32-S3 N16R8（16MB Flash，8MB PSRAM）
- USB：ESP32-S3 原生 USB OTG，作为 USB Device 连接电脑
- 当前测试平台：1 个摇杆元件 + 4 个按钮元件
- 最终目标：替换为正式游戏手柄的按键与摇杆

## 3. 软件技术栈（已确定）
- 框架：**ESP-IDF**（不使用 Arduino）
- USB 协议栈：**TinyUSB**（ESP-IDF 内置）
- 操作系统：**FreeRTOS**（ESP-IDF 内置）
- 存储：**NVS**（非易失性存储）
- 上位机：Windows，使用 **hidapi** 通过 HID Feature Report 与设备通信
- 开发语言：C/C++

## 4. 功能需求

### 4.1 键盘映射
- 摇杆映射为 WASD 或方向键，需设置死区（10%~15%），支持斜向输入（同时触发两个方向键）。
- 4 个按钮映射为可配置的键盘按键。
- 支持按键防抖：时间窗口防抖，连续 N 次扫描稳定后才确认状态变化。

### 4.2 完全模拟实体键盘
- 使用成熟键盘厂商的 VID/PID（例如罗技 K2600：VID 0x24AE, PID 0x2003）。
- 生成符合该厂商格式的**唯一序列号**（不得与真实键盘重复），避免 Windows 代码 42 冲突。
- 定制 USB 描述符：Manufacturer String、Product String、Serial Number String 均需符合目标厂商规范。
- 关闭所有串口调试输出，量产固件不保留 UART 通信。
- 模拟真实键盘行为：LED 状态报告、空闲报告等。
- 所有配置命令通过 HID Feature Report 传输，不暴露额外接口。

### 4.3 Windows 上位机配置软件
- 使用 hidapi 枚举并连接设备。
- 通过 HID Feature Report 读写配置：
  - 读取当前键位映射、宏定义。
  - 下发新的键位映射、宏定义。
- 提供“保存到设备”按钮，点击后才将完整配置写入 NVS。
- 界面需支持：单键宏编辑、组合键宏编辑、随机延迟范围设置。

### 4.4 宏功能
- 支持单键宏（如按下按钮触发一连串按键）和组合键宏（如 Ctrl+C）。
- 宏步骤中可插入随机延迟。
- **随机延迟质量要求**：延迟分布需接近人类操作特征，避免窄范围均匀分布。
  - 基础按键间隔：30–150ms，偏向较低值。
  - 组合键间隔：100–300ms。
  - 长宏中偶尔插入 1–3 秒的“犹豫”停顿。
  - 随机数种子必须使用 `esp_random()` 或 ADC 噪声，不能固定。
- **宏引擎必须非阻塞**：使用 FreeRTOS 任务 + 状态机，禁止使用 `delay()` 阻塞系统。
- 宏执行设置最大超时（如 30 秒），超时强制终止并释放所有按键。

### 4.5 NVS 断电保存
- 配置数据存储在 NVS 中，断电不丢失。
- 免驱使用：设备枚举后自动加载 NVS 配置。
- **磨损控制**：
  - 延迟批量写入，仅在收到上位机“保存”命令时写入一次。
  - 固件内设置写入频率限制（如一分钟内最多写一次）。
  - 写入失败时不阻塞系统，使用 RAM 临时配置继续工作。

### 4.6 故障保护
- 启用任务看门狗（TWDT），注册按键扫描任务和宏任务，超时自动复位。
- USB 断开时清空所有按键报告，发送全零报告。
- 固件启动时、USB 重新枚举前，先发送一次全零 HID 报告，确保主机端按键状态归零。
- 宏执行超时保护。
- 看门狗复位后重新枚举，确保所有按键处于释放状态。

## 5. 系统架构设计

### 5.1 双核任务分配
Core 0:
├── 按键/摇杆扫描任务（高优先级，1ms 周期）
└── HID 报告发送任务（事件驱动）

Core 1:
├── 宏执行引擎（非阻塞状态机）
├── HID Feature Report 处理任务（配置接收/回传）
└── NVS 配置管理任务（延迟批量写入）

### 5.2 数据流
- 按键扫描 → 映射表 → HID 报告队列 → USB 发送
- 上位机 → HID Feature Report → 配置解析 → RAM 配置 → 保存按钮 → NVS
- 宏触发 → 宏引擎状态机 → 按键事件 → HID 报告队列

### 5.3 模块划分
- `usb_descriptors.c`：USB 描述符定制（VID/PID/序列号/字符串）
- `hid_keyboard.c`：HID 报告发送、Feature Report 处理
- `input_scan.c`：按键/摇杆扫描、防抖、ADC 采样
- `keymap.c`：键位映射表管理
- `macro_engine.c`：宏解析、非阻塞执行、随机延迟
- `nvs_config.c`：NVS 读写、延迟批量保存
- `watchdog.c`：看门狗初始化与任务注册
- `main.c`：任务创建、初始化流程

## 6. 关键实现要点与注意事项

1. **USB 描述符**：序列号必须唯一，格式符合目标厂商规范。TinyUSB 默认序列号可能为 "123456"，必须显式覆盖。
2. **随机延迟**：使用 `esp_random()` 初始化种子。延迟分布参考人类操作：平均约 112ms，标准差约 38ms，避免标准差低于 ±5ms。
3. **非阻塞宏**：使用 `millis()` 或 FreeRTOS `vTaskDelayUntil` 实现状态机，禁止 `delay()`。
4. **NVS 磨损**：使用 NVS 命名空间隔离配置，写入前检查频率限制，失败时回退到 RAM 配置。
5. **看门狗**：在 `app_main` 中初始化 TWDT，将按键扫描任务和宏任务加入监控，超时时间建议 3–5 秒。
6. **启动保护**：在 USB 枚举前发送全零 HID 报告，确保主机端无残留按键状态。
7. **防抖**：每个按键独立计数器，连续 5 次扫描稳定才确认状态变化。
8. **摇杆死区**：中心区域 10%~15% 不触发，支持斜向输入逻辑。
9. **供电**：确认 USB 总线供电充足（最大 500mA），必要时增加滤波电容。

## 7. 开发阶段规划
1. **阶段一**：测试平台跑通 USB HID 键盘基础功能（摇杆+4按钮映射）。
2. **阶段二**：集成 NVS 配置保存与加载，实现上位机 Feature Report 通信。
3. **阶段三**：实现宏引擎（单键、组合键、随机延迟）。
4. **阶段四**：加入故障保护（看门狗、启动全零报告、宏超时）。
5. **阶段五**：定制 USB 描述符，伪装成熟厂商设备，测试反作弊环境识别率。
6. **阶段六**：替换为正式游戏手柄硬件，完成最终集成。
